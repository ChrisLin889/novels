# 小说网站开发者文档

## 项目架构

本项目采用前后端分离的架构设计，前端使用 Vue.js 构建单页应用，后端使用 Flask 提供 RESTful API 服务。

### 整体架构

```
+-------------+       +---------------+       +---------------+
|             |       |               |       |               |
|   Browser   | <---> |   Frontend    | <---> |    Backend    |
|             |       |   (Vue.js)    |       |    (Flask)    |
+-------------+       +---------------+       +------+--------+
                                                     |
                                              +------v--------+
                                              |               |
                                              |   Database    |
                                              |   (MySQL)     |
                                              +---------------+
```

## 技术栈

### 前端
- **框架**: Vue 3
- **状态管理**: Vuex 4
- **路由**: Vue Router 4
- **UI库**: Element Plus
- **HTTP请求**: Axios
- **构建工具**: Vue CLI / Vite

### 后端
- **框架**: Flask
- **ORM**: SQLAlchemy
- **数据库**: MySQL
- **缓存**: Redis
- **认证**: JWT (JSON Web Tokens)
- **文档**: Swagger / Flask-RESTx

## 前端开发指南

### 组件开发规范

1. **命名规范**
   - 组件文件使用 PascalCase (如 `NovelCard.vue`)
   - 组件名称与文件名保持一致
   - 页面级组件放在 `views` 目录
   - 可复用组件放在 `components` 目录

2. **样式规范**
   - 使用 SCSS 预处理器
   - 组件样式使用 scoped 属性
   - 公共样式放在 `assets/styles` 目录
   - 遵循 BEM 命名规范

3. **API调用**
   - 所有API请求定义在 `api` 目录
   - 通过 Vuex actions 调用 API
   - 处理请求状态和错误

### 状态管理

Vuex 模块化管理状态:

- **user**: 用户信息、认证状态
- **novel**: 小说列表、详情、阅读状态
- **author**: 作者信息、作品管理
- **admin**: 管理后台状态

## 后端开发指南

### API设计原则

1. **RESTful API设计**
   - 使用标准HTTP方法 (GET, POST, PUT, DELETE)
   - 使用复数名词表示资源集合
   - 使用资源层级结构

2. **响应格式**
   ```json
   {
     "code": 200,
     "message": "Success",
     "data": { ... }
   }
   ```

3. **错误处理**
   ```json
   {
     "code": 400,
     "message": "Bad Request",
     "errors": ["Invalid username format"]
   }
   ```

### 认证与授权

使用JWT (JSON Web Tokens) 进行身份验证:

- 登录时生成 token
- 使用 `@jwt_required` 装饰器保护API
- 在请求头中携带 token: `Authorization: Bearer <token>`

### 中间件

1. **CORS 处理**
2. **请求日志记录**
3. **异常处理**
4. **认证与授权**

### 服务层

业务逻辑封装在 service 层:

```python
# app/services/novel_service.py
def get_novel_detail(novel_id):
    # 从数据库获取小说详情
    novel = Novel.query.get(novel_id)
    if not novel:
        raise NotFoundError("Novel not found")
    
    # 转换为 DTO
    return {
        "id": novel.id,
        "title": novel.title,
        "author": novel.author.name,
        "category": novel.category.name,
        "description": novel.description,
        "cover_url": novel.cover_url,
        "status": novel.status,
        "word_count": novel.word_count,
        "chapters_count": len(novel.chapters),
        "created_at": novel.created_at.isoformat(),
        "updated_at": novel.updated_at.isoformat()
    }
```

## 部署流程

### 开发环境

1. **前端**
   ```bash
   cd frontend
   npm install
   npm run serve
   ```

2. **后端**
   ```bash
   cd backend
   pip install -r requirements.txt
   flask run
   ```

### 测试

1. **前端测试**
   ```bash
   npm run test:unit  # 单元测试
   npm run test:e2e   # 端到端测试
   ```

2. **后端测试**
   ```bash
   pytest             # 运行所有测试
   pytest tests/test_novel_api.py  # 运行特定测试
   ```

### 生产环境

1. **前端构建**
   ```bash
   npm run build
   ```

2. **后端部署**
   - 使用 Gunicorn 作为WSGI服务器
   - 使用 Nginx 作为反向代理
   - 配置 SSL 证书

   ```bash
   gunicorn -w 4 -b 127.0.0.1:5000 run:app
   ```

3. **Nginx配置**
   ```nginx
   server {
       listen 80;
       server_name example.com;
       
       # 重定向到HTTPS
       return 301 https://$host$request_uri;
   }

   server {
       listen 443 ssl;
       server_name example.com;
       
       ssl_certificate /path/to/cert.pem;
       ssl_certificate_key /path/to/key.pem;
       
       # 前端静态文件
       location / {
           root /path/to/frontend/dist;
           try_files $uri $uri/ /index.html;
       }
       
       # API请求代理
       location /api {
           proxy_pass http://127.0.0.1:5000;
           proxy_set_header Host $host;
           proxy_set_header X-Real-IP $remote_addr;
       }
   }
   ```

## 常见问题与解决方案

### 前端常见问题

1. **跨域请求失败**
   - 检查后端CORS配置
   - 确认API请求地址正确

2. **组件通信问题**
   - 小范围使用props和events
   - 跨组件通信使用Vuex

### 后端常见问题

1. **数据库连接超时**
   - 检查连接池配置
   - 优化长时间运行的查询

2. **内存泄漏**
   - 检查资源是否正确释放
   - 使用性能分析工具定位问题
