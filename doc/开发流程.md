### 开发流程与测试要求设计

---

#### **一、开发流程阶段划分**

| **阶段**        | **核心任务**                                           | **交付物**                     |
| ------------- | -------------------------------------------------- | --------------------------- |
| **1. 环境搭建**   | 安装开发工具链（Python/Node.js/MySQL/Redis）、初始化项目仓库、配置基础依赖 | 可运行的基础开发环境、Git仓库结构文档        |
| **2. 数据库设计**  | 根据功能文档创建MySQL表结构，定义索引与约束，初始化测试数据                   | 完整的SQL建表脚本、ER图、测试数据初始化脚本    |
| **3. 核心模块开发** | 按优先级实现用户模块、小说模块、缓存模块等核心功能（参考模块设计文档）                | 可运行的模块代码、接口文档（Swagger/YAPI） |
| **4. 前后端联调**  | 对接API接口，实现基础功能链路（注册→浏览→阅读→评论）                      | 可演示的完整功能原型、接口联调报告           |
| **5. 数据导入模块**   | 开发数据导入功能并集成到Flask，实现数据验证→处理→入库流程              | 可运行的导入接口、数据验证机制、入库验收报告           |
| **6. 管理端开发**  | 实现内容审核、用户管理、数据统计等后台功能                              | 管理端功能清单、权限验证测试用例            |
| **7. 优化与验收**  | 性能调优（MySQL索引/Redis缓存）、安全加固、响应式布局完善                 | 性能测试报告、安全扫描报告、多设备兼容性报告      |

---

#### **二、各阶段测试要求**

##### **1. 环境搭建阶段**

- **测试目标**：验证基础环境可用性

- **测试内容**：
  
  markdown
  
  复制
  
  1. Python 3.8+与Node.js 16+版本校验
  2. MySQL 8.0连接测试（`mysql -u root -p`）
  3. Redis PING命令响应验证
  4. Vue/Flask脚手架项目成功启动

- **通过标准**：所有组件安装正确且无报错

##### **2. 数据库设计阶段**

- **测试目标**：确保表结构符合功能需求

- **测试内容**：
  
  markdown
  
  复制
  
  1. 执行建表脚本后，检查`user`/`novel`/`chapter`等核心表是否存在
  2. 验证外键约束（如`chapter.novel_id`关联`novel.id`）
  3. 测试复合索引性能（`SELECT * FROM novel WHERE category='玄幻'`响应时间<100ms）
  4. 数据完整性测试（如删除小说时级联删除章节）

- **通过标准**：所有DDL执行成功，索引命中率>95%

##### **3. 核心模块开发阶段**

- **测试目标**：模块功能独立可用

- **测试方法**：
  
  markdown
  
  复制
  
  - **用户模块**：
    
    1. 注册接口：模拟100并发注册，检查密码哈希存储
    2. 登录接口：错误密码锁定策略验证
    3. 权限校验：普通用户访问管理接口返回403
  
  - **小说模块**：
    
    1. 分页查询：第100页数据返回时间<1s
    2. 阅读量统计：刷新页面后`novel.view_count`自动+1
    3. 书签同步：多设备登录后进度一致性验证

- **通过标准**：单元测试覆盖率>80%，Pytest通过率100%

##### **4. 前后端联调阶段**

- **测试目标**：验证端到端功能链路

- **测试场景**：
  
  markdown
  
  复制
  
  1. 完整用户旅程测试：
     注册 → 登录 → 搜索"修仙" → 收藏小说 → 阅读第一章 → 发表评论
  
  2. 异常场景测试：
     
     - 未登录用户访问个人中心 → 跳转登录页
     - 输入超长评论（>1000字）→ 前端截断并提示
     - 断网状态下阅读 → 错误友好提示

- **通过标准**：关键路径功能无阻塞，错误处理符合预期

##### **5. 数据导入模块阶段**

- **测试目标**：保证数据导入与处理可靠性

- **测试内容**：
  
  markdown
  
  复制
  
  1. 导入接口测试：访问`/import/novel`成功创建小说
  2. 数据验证测试：不完整的数据导入被正确拒绝并返回错误信息
  3. 批量导入测试：通过一次请求成功导入小说及其多个章节
  4. 格式兼容测试：支持多种格式（JSON、TXT）的数据导入

- **通过标准**：导入成功率>95%，数据完整性100%，验证机制可靠

##### **6. 管理端开发阶段**

- **测试目标**：确保后台管控能力

- **测试用例**：
  
  markdown
  
  复制
  
  1. 敏感词过滤：发布含"暴力"的评论 → 自动拦截并记录日志
  2. 用户封禁：禁用账号后尝试登录 → 返回"账号已冻结"
  3. 数据导出：点击"导出CSV" → 文件包含完整支付记录
  4. 榜单刷新：手动更新Redis缓存 → 首页立即显示新榜单

- **通过标准**：所有管理操作可追溯且数据可审计

##### **7. 优化与验收阶段**

- **测试目标**：系统达到上线标准

- **测试类型**：
  
  markdown
  
  复制
  
  1. **性能测试**：
     
     - 首页加载时间 < 1.5s（Redis缓存命中时）
     - 500并发用户阅读操作 → 平均响应时间 < 2s
  
  2. **安全测试**：
     
     - SQL注入攻击：`' OR 1=1 --`输入 → 返回空结果
     - XSS攻击：提交`<script>alert(1)</script>` → 内容被转义
  
  3. **兼容性测试**：
     
     - Chrome/Firefox/Safari核心功能一致
     - 移动端屏幕适配（375px~1440px）

- **通过标准**：性能指标达标，OWASP Top 10漏洞清零

---

#### **三、测试工具推荐**

- **单元测试**：Pytest（Python）、Jest（Vue）

- **接口测试**：Postman + Newman（自动化测试集）

- **性能测试**：Locust（模拟高并发）、MySQL Explain分析

- **安全测试**：SQLMap（注入检测）、ZAP（漏洞扫描）

- **UI测试**：Cypress（端到端测试）

---

### 总结

本流程采用**渐进式开发+分层测试**策略：

1. 优先保证核心模块可用性（用户/小说/缓存）

2. 通过联调测试验证关键业务流程

3. 最终聚焦性能与安全验收  
   测试要求覆盖单元测试→集成测试→系统测试全链条，确保毕业设计在有限时间内交付可用、可靠的系统。
