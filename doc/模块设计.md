### 模块设计（低耦合高内聚）

---

#### **1. 模块划分与职责**

| **模块名称** | **核心职责**                           | **依赖关系**       |
| -------- | ---------------------------------- | -------------- |
| **用户模块** | 用户注册/登录、个人信息管理、权限验证（普通用户/作者/管理员）   | 无              |
| **小说模块** | 小说元数据管理、章节内容加载、阅读记录跟踪、分类与榜单生成      | 用户模块（权限验证）     |
| **互动模块** | 评论发布/管理、打赏记录、用户关注、私信功能             | 用户模块、小说模块      |
| **搜索模块** | 关键词全文搜索、高级筛选（分类/字数/更新时间）           | 小说模块           |
| **爬虫模块** | 外部数据采集、数据清洗、临时表存储、审核触发             | 无（通过接口与小说模块交互） |
| **管理模块** | 内容审核（小说/评论）、用户封禁、数据统计（流量/收益）、敏感词维护 | 用户模块、小说模块、互动模块 |
| **缓存模块** | 首页榜单缓存（热销榜/新书榜）、高频数据预加载            | 小说模块           |
| **工具模块** | 敏感词过滤、数据格式校验、加密工具（密码哈希）、日志记录       | 所有模块（公共依赖）     |

---

#### **2. 模块交互设计**

##### **模块间通信原则**

- **接口定义**：模块通过**明确API接口**交互（如`UserService.check_permission()`）。

- **数据隔离**：模块仅能访问自身数据库表，跨表操作通过接口调用。

- **事件驱动**：关键操作触发事件（如“用户打赏”触发通知作者），避免直接依赖。

##### **典型场景示例**

1. **用户发表评论**：
   
   复制
   
   前端 → 互动模块.submit_comment() 
   → 调用工具模块.filter_sensitive_words() 
   → 调用用户模块.check_user_status() 
   → 调用小说模块.get_chapter_info() 
   → 写入数据库

2. **爬虫数据入库**：
   
   复制
   
   爬虫模块.crawl_data() → 写入临时表 
   → 管理模块.approve_data() 
   → 调用小说模块.insert_novel() 
   → 触发缓存模块.refresh_ranking()

3. **首页加载榜单**：
   
   复制
   
   前端 → 小说模块.get_ranking() 
   → 优先查询缓存模块 
   → 缓存未命中时从MySQL聚合数据 
   → 更新缓存

#### **3. 模块内部设计（以用户模块为例）**

##### **类结构**

python

复制

class UserService:
    # 对外接口
    def register(phone, password): ...
    def login(phone, password): ...
    def get_user_info(user_id): ...
    def check_permission(user_id, role): ...

class UserDAO:
    # 数据操作（仅操作user表）
    def create_user(): ...
    def query_user_by_phone(): ...
    def update_user_profile(): ...

class AuthUtils:
    # 内部工具（密码哈希/JWT生成）
    def hash_password(): ...
    def generate_token(): ...

##### **内聚性体现**

- **功能集中**：所有用户相关操作（注册、登录、鉴权）在`UserService`中完成。

- **数据封闭**：`UserDAO`仅操作`user`表，不涉及其他业务逻辑。

- **工具隔离**：密码哈希和Token生成由`AuthUtils`独立处理。

##### **低耦合设计**

- 其他模块需验证权限时，调用`UserService.check_permission()`，无需知晓实现细节。

- 修改密码加密算法时，只需调整`AuthUtils`，不影响其他模块。

---

#### **4. 模块解耦关键设计**

1. **数据库解耦**：
   
   - 每个模块拥有独立DAO类（如`NovelDAO`仅操作`novel`表）。
   
   - 跨表操作通过服务接口调用（如互动模块删除评论时，调用`UserService.check_permission()`）。

2. **缓存透明化**：
   
   - 缓存模块提供统一接口（如`cache.get("hot_ranking")`），业务模块无需关心缓存策略。

3. **事件总线**：
   
   - 定义全局事件（如`EVENT_CHAPTER_UPDATE`），模块可订阅/触发事件。
   
   - 示例：小说模块更新章节后触发事件，搜索模块自动重建索引。

4. **依赖注入**：
   
   - 模块间通过构造函数注入依赖（如`NovelService(user_service: UserService)`）。
   
   - 测试时可替换为Mock对象，提升可测试性。

#### **6. 总结**

- **低耦合**：通过接口隔离、事件通信、依赖注入，模块间仅通过明确定义的API交互。

- **高内聚**：每个模块聚焦单一职责（如用户模块仅处理用户相关逻辑），内部类高度协作。

- **扩展性**：新增功能时（如推荐系统），只需添加独立模块并订阅相关事件，无需修改现有代码。
